# 底层 BIOS & UEFI 原理

## UEFI / BIOS 基础硬件结构

### 传统主板

- CMOS：有 CMOS ，RTC 时间存放在 CMOS RAM 中，RTC 纽扣电池没电即丢失
- BIOS配置存放位置：CMOS (RAM)，通常只有 128~256 字节的极小容量，纽扣电池没电即丢失

> （PCH/南桥）内部集成的 CMOS (计算机范畴内与 CMOS RAM 为同一个东西) 属于易失性存储，断电后数据会立即消失。因此它**完全依赖主板上的 CR2032 纽扣电池**持续供电来维持记忆。


#### 为什么现在“扣电池/短接 Clear CMOS”还能重置设置？

既然现代主板把设置写进了不怕断电的 BIOS Flash 里，为什么抠掉纽扣电池或按下主板上的 Clear CMOS 按钮依然能重置 BIOS？

1. **RTC 时钟与状态标志位复位：** 主板上的实时时钟（RTC）电路和硬件配置标志位依然靠纽扣电池供电。
2. **触发默认加载机制：** 当你抠掉电池或短接 Clear CMOS 跳线时，RTC 电路断电复位，系统再次开机时检测到“CMOS 校验和错误（Checksum Error）”或复位信号，BIOS 就会自动跳过 NVRAM 中保存的用户设置，强制重新加载出厂默认配置（Optimized Defaults），并覆盖或清空 NVRAM。


### 现代主板

- CMOS：无 CMOS ，RTC 计数器集成在 PCH / SoC 内部，RTC 纽扣电池没电即丢失 
- BIOS配置存放位置：BIOS Flash 芯片内部划出的非易失性存储区（NVRAM，Non-Volatile RAM），纽扣电池没电依旧保存配置。


> PCH（南桥）趋于集成到 CPU 内部（非区分 UEFI 或 Legacy BIOS 的条件）

## UEFI / BIOS 配置存放位置

用户修改的 BIOS 设置主要存放在 **BIOS Flash 芯片内的 NVRAM 区域**（现代 UEFI 模式）或 **CMOS RAM**（传统 BIOS 模式）中，具体取决于主板架构：

* UEFI:
  * **现代主板（UEFI 模式）：存放在 BIOS Flash（SPI Flash ROM）**
  * **存储位置：** 现代主板会将你修改的配置直接写入 BIOS Flash 芯片内部划出的非易失性存储区（NVRAM，Non-Volatile RAM）。
  * **特点：** Flash 属于非易失性存储（类似 Flash 闪存）。这意味着即使电脑完全关机、拔掉电源线，甚至主板上的纽扣电池没电，你保存的配置**依然不会丢失**。

* Legacy BIOS:
  * **传统主板（Legacy BIOS 模式）：存放在 CMOS RAM**
  * **存储位置：** 早期的 BIOS 设置保存在主板芯片组（PCH/南桥）内部集成的 **CMOS RAM** 中（通常只有 128~256 字节的极小容量）。
  * **特点：** CMOS 属于易失性存储，断电后数据会立即消失。因此它**完全依赖主板上的 CR2032 纽扣电池**持续供电来维持记忆。

## UEFI & BIOS 模式

### 核心对比一览

| 维度 | UEFI 模式（纯 UEFI） | Legacy BIOS 模式（传统模式） | UEFI/Legacy 兼容模式（CSM） |
| --- | --- | --- | --- |
| **底层架构** | 现代 32/64 位 C 语言架构 | 传统 16 位实模式（8086 时代产物） | UEFI 框架下运行 Legacy 模拟层 |
| **硬盘分区格式** | 必须采用 **GPT** | 必须采用 **MBR** | 支持 GPT 与 MBR 混合识别 |
| **单盘容量限制** | 无实际限制（最大支持 9.4 ZB） | 单盘最大仅支持 **2 TB** | 视系统所在盘的格式（MBR/GPT）而定 |
| **启动速度** | 快（并行初始化硬件，支持快速启动） | 慢（逐个自检硬件，等待时间长） | 较慢（需加载 CSM 兼容模块） |
| **安全特性** | 支持 Secure Boot（安全启动）、TPM | 无 Secure Boot 防御能力 | 启用 CSM 时通常强制禁用 Secure Boot |
| **主操作系统** | Windows 11 / 10（64位）、现代 Linux | Windows 7 及更早系统、32位系统 | 用于老系统迁移或旧双系统共存 |

> 注意：由 现代UEFI 切换的 Legacy BIOS 或 UEFI/Legacy兼容 模式，其底层还是 UEFI 架构，比如无CMOS。

### 三种模式的具体工作原理

#### 1. UEFI 模式（Native UEFI）

* **运行机制：** 抛弃了 16 位实模式限制，可以直接在 32 位或 64 位保护模式下直接初始化硬件，并读取 GPT 分区中的 ESP（EFI 系统分区）里的 `.efi` 引导文件。
* **主要优势：** 支持图形化高分辨率界面、鼠标操作、网络连通；支持超过 2 TB 的大容量硬盘；具备 Secure Boot 防御 Bootkit/Rootkit 恶意病毒。
* **适用场景：** 安装 Windows 11、Windows 10（64位）以及最新的 Linux 发行版。

#### 2. Legacy BIOS 模式（纯传统模式）

* **运行机制：** 开机后按顺序自检（POST），随后读取硬盘第一个扇区（主引导记录 MBR），执行其中的 512 字节引导代码。
* **主要局限：** 无法直接识别超过 2 TB 的硬盘（超出的空间无法分配）；主分区数量不能超过 4 个；启动过程逐个排查外设，效率低下。
* **适用场景：** 老旧电脑、32 位操作系统或仅支持 MBR 引导的古董软件环境。

#### 3. UEFI/Legacy 兼容模式（CSM 模式）

* **运行机制：** **它的底层依然是 UEFI**，但在 UEFI 固件内部加载了一个名为 **CSM（Compatibility Support Module，兼容性支持模块）** 的软件层，用以模拟传统 BIOS 的中断响应和 MBR 引导流程。
* **核心作用：** 解决过渡期的兼容问题。在此模式下，系统会先尝试按 UEFI 方式寻找 GPT 引导；如果找不到，再降级使用 Legacy 模式去寻找 MBR 引导。
* **适用场景：** 需要在一台较新的主板上安装 Windows 7，或者硬盘上存有老的 MBR 系统盘需要直接挂载启动。


### 选型建议

1. **安装 Windows 11：** 必须使用 **纯 UEFI 模式**（必须关闭 CSM），因为 Windows 11 强制要求 GPT 分区表与 Secure Boot / TPM 2.0。
2. **现代主流电脑（Intel 11代/AMD 锐龙 5000 及更新平台）：** 建议直接选择 **纯 UEFI**。许多现代主板和独显（如 PCIe 4.0/5.0 显卡）在开启 CSM 后甚至会导致无法正常出图或触发报错。
3. **旧盘接管与老系统：** 仅当需要运行 Windows 7、老版 PE 工具箱或恢复旧 MBR 格式硬盘上的系统时，才需要开启 **UEFI/Legacy 兼容模式（CSM）**。
